# Mindloom — Data Model

Relational data lives in **Supabase-hosted PostgreSQL**; embeddings live in the same database via **pgvector** (see `Architecture.md` §7a). IDs are UUIDs (`uuid`, generated by the app; API returns them as strings). Timestamps are `timestamptz` (UTC). `JSON` columns are `jsonb`. Types written as `TEXT` below are Postgres `text`.

## 1. Entity overview

```
workspaces 1─* pages 1─* tab_sessions
workspaces 1─* edges  (source_page_id, target_page_id → pages)
workspaces 1─* groups 1─* group_members *─1 pages
workspaces 1─* tags   *─* taggings (page | group)
workspaces 1─* notes  (target: page | group)
pages 1─1 page_analysis   (summary, keywords, simhash, embedding)
workspaces 1─* share_links
workspaces 1─* processing_jobs
workspaces 1─* event_log  (for WS seq)
```

### tab_sessions  (browser tab identity — separate from pages)

UNIQUE `(workspace_id, browser_tab_id, page_id)`. Closing a tab updates `state` only; the page is untouched. Multiple tab_sessions may reference one page.

### ingest_events (internal retry receipts, Phase 3)

`(workspace_id UUID FK → workspaces ON DELETE CASCADE, client_event_id UUID)` is the composite primary key. `response_body JSONB` and `status_code INTEGER` preserve the first successful ingest response. This table is internal to the backend; it adds no API fields. Reservation, page/tab upserts, and receipt storage happen in one transaction so a retry with the same event ID returns the original response.

### edges
| Column | Type | Notes |
|---|---|---|
| id | TEXT PK | |
| workspace_id | TEXT FK | |
| source_page_id, target_page_id | TEXT FK → pages ON DELETE CASCADE | |
| type | TEXT | `related_to|source_of|answers|supports|references|navigated_to|duplicate_of|custom` |
| label | TEXT NULL | for `custom` |
| origin | TEXT | `suggested|manual` |
| status | TEXT | `suggested|accepted|rejected` (manual edges are always `accepted`) |

| evidence | JSON NULL | see §3 |
| created_at, updated_at | TIMESTAMP | |

Constraints: `CHECK(source_page_id <> target_page_id)`; UNIQUE `(workspace_id, source_page_id, target_page_id, type)`. Rejected rows are **tombstones** that block re-suggestion of the same pair (any type).

## 3. JSON shapes

**edges.evidence**
```json
{
  "method": "embedding_cosine+keywords",
  "score": 0.62,
  "shared_keywords": ["triage", "emergency"],
  "snippets": [
    {"page_id": "p1", "text": "AI triage reduces wait times..."},
    {"page_id": "p2", "text": "Emergency departments are adopting triage models..."}
  ]
}
```
Manual edges: `evidence = null` (UI shows "Created by you").

**workspaces.view_state**
```json
{"mode":"graph","zoom":1,"pan":{"x":0,"y":0},"focus":{"type":"group","id":"g1","hops":1},
 "filters":{"tags":[],"domains":[],"status":[]},"selected":{"type":"page","id":"p1"},"sort":"recent"}
```

**workspaces.settings**
```json
{"edge_threshold":0.35,"louvain_resolution":1.0,"auto_recompute":true}
```

## 4. Lifecycle rules

- **Delete page** → cascades tab_sessions, analysis, edges, group_members; notes/taggings removed by service; optional `blocked_urls` (in `settings`) prevents re-adding.
- **Delete workspace** → cascades everything.
- **Recompute** → inside one transaction: delete `origin=suggested AND status=suggested` edges & suggested groups (that were never edited), insert new candidates excluding pairs with a tombstone or manual edge; emit `graph.changed`.
- **Promotion** → editing a suggested group/edge sets `origin=manual` (groups) or `status=accepted` (edges) so recompute leaves it.
- **Restore rejected** → delete the tombstone row (pair becomes eligible again at next recompute).

## 5. Migrations

Alembic from day one, run against the **direct** Supabase connection; the app uses the pooled connection. The planned full schema includes all tables, the `tsvector` column and GIN index, and an HNSW index on `page_analysis.embedding`.

Current implementation is phased: migration 0 runs `CREATE EXTENSION IF NOT EXISTS vector;`; migration 1 creates `workspaces`, `pages`, and `tab_sessions` with the page `tsvector`/GIN index; migration 2 adds internal `ingest_events`; migration 3 adds `page_analysis` with `vector(384)` and its cosine HNSW index, `edges`, `groups`, `group_members`, `processing_jobs`, and `event_log`. Notes, tags, shares, and generated graph merge logic remain for later phases.
